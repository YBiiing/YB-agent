# 第一阶段计划：基础 Agent

版本 1.0 · 2026-10-20 · 状态：已授权实施，P1-01 至 P1-10 已完成，P1-11 进行中；实际结果见 IMPLEMENTATION_LOG.md。

规范依据：[总体设计与执行契约](DESIGN.md)。扩展目标见[第二阶段计划](PHASE2_PLAN.md)。

## 1. 目标与交付物

交付一个单进程、单执行者、串行工具的真实单 Agent：能够理解任务、进行多轮模型决策、执行受控工具、根据反馈继续行动，并提交带验证依据的结果。用户能审批、暂停、继续、取消和查看记录。

交付包括 V2 核心、真实及 mock 模型适配、文件与命令工具、控制入口、本地审计与制品、CLI、固定任务集、测试与评测报告、安装/使用/限制文档。V2 能力不以旧版已有测试或脚本化演示代替验收。

第一阶段不交付自动崩溃续跑、PostgreSQL、Worker 租约、跨进程接管、长期记忆、RAG、完整 WebUI 或 Multi-Agent。复杂能力保留在第二阶段，不在本阶段提前实现。

## 2. 执行约定与新旧兼容

- 采用 Python 语言连续性，保留现有 `harness` 入口和旧版配置语义；V2 独立入口规定为 `harness-v2`。
- 新核心与测试拟放 `src/v2/`、`tests/v2/`，文档和评测材料按阶段任务建立。P1-01 核对打包和测试发现配置后确认准确路径。
- 最小 CLI：`harness-v2 --project <path> --task <text>`；控制以明确 run_id 为目标。具体交互命令在 P1-07 完成前写入使用文档。
- 本地审计采用 DESIGN §6 的文件归档，不作为恢复状态库；默认不要求任何后台服务。
- Windows 和 Linux 都要验证所声称支持的控制、路径、进程行为；无法达到的保证不能用“跨平台”笼统掩盖。
- 不自动提交、推送、发布，不将仓库任务授权推断为生产或外部写入授权。

## 3. 依赖与里程碑

```text
P1-01 基线与入口
  -> P1-02 协议与状态 -> P1-03 只读切片与评测冻结
  -> P1-04 真实模型与初始基线
  -> P1-05 策略审批 -> P1-06 写入/命令与反馈
  -> P1-07 运行控制与预算
  -> P1-08 上下文与输出
  -> P1-09 审计、证据和验收
  -> P1-10 正确性回归
  -> P1-11 CLI与兼容交付
  -> P1-12 固定评测与G1
```

这是主依赖链，不要求已经实现的安全、日志、测试等到后续任务才出现。P1-03 起有最小记录；P1-04 只开放已治理的只读工具；写入和命令必须等 P1-05 的策略机制。任务按边界顺序推进，不预设可并行修改同一引擎。

| 里程碑 | 对应任务 | 可演示产出与通过条件 |
| --- | --- | --- |
| 1.1：最小执行闭环 | P1-01 至 P1-04 | mock 与真实模型的受控多步只读任务；模型根据观测继续，保留真实基线 |
| 1.2：治理与运行控制 | P1-05 至 P1-07 | 受控修改与验证、动作审批、暂停/继续和取消；错误路径可确定性复现 |
| 1.3：上下文、记录与验证 | P1-08 至 P1-10 | 有界输入、完整结果、证据与验收报告；跨模块契约场景回归通过 |
| 1.4：独立使用与 G1 | P1-11 至 P1-12 | 新环境可使用的 CLI、完整任务评测与限制说明；达到全部 G1 条件 |

里程碑成果必须沿已有纵向切片增量交付；不能到 1.4 才第一次运行真实 Agent。日志、限制、输出制品和必要测试随相应工具出现，不等待最终整理任务。
