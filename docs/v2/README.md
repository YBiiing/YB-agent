## 阶段门槛

- **G1：基础版本完成。** 第一阶段全部必需任务、确定性检查及真实任务发布门槛通过；结果、环境和限制均有记录。
- **G2-R：恢复能力完成。** 第二阶段恢复相关任务通过真实进程中断、重复投递、接管和副作用不确定性验证。
- **G2：扩展版本完成。** 规划、上下文增强、记忆与 RAG、完整应用、Multi-Agent 及整体交付验收完成。

G1 本身是完整、可展示的成果。G2-R 不能替代 G1，也不能据此宣称整个第二阶段已经完成。

## 本次定稿说明

本版落实已确认的两阶段范围：第一阶段交付基础单 Agent，第二阶段交付 B 崩溃恢复与复杂扩展。总体设计和任务分解是实施依据，不表示实现已经完成，也不把本次文档授权扩大为实施授权。

0.2 在现有方案上统一了评测冻结顺序，取消未经基线支持的固定通过率；补充暂停后的批次保留、控制与终态的先后规则，以及每个里程碑的可演示产出。精确依赖版本、平台实现和能力阈值须在指定任务中解决，未解决时阻断相应验收。

0.3 修订首轮独立审查保留的四项问题：模型请求与控制命令的启动排序、第二阶段继续满足 G1 发布门槛、能力失败样本与阻断缺陷的区别，以及 P1-06 完成前冻结阈值的准确时点；同时澄清最小恢复入口不等于已存在 HTTP API。

1.0 在三项独立二次审查完成后定稿。复审确认上述问题已闭合，未报告新增 P1/P2/P3 问题。相对已复审的 0.3，1.0 仅更新版本、状态、阅读入口并保存审查记录，执行契约与任务范围保持一致。结论仅适用于规划文本，不代表实现或运行验收已完成，详见审查记录。

## 状态与变更纪律

所有计划项初始均为未开始，文中的验收是未来要求，不是已有测试结果。实施前重新检查代码和工作区；本方案不预设当前 v0.1.1 测试已经通过。

范围发生变化时，先修改 `DESIGN.md` 的范围表与决定记录，再同步对应阶段计划。第一阶段新增恢复、分布式调度或大型依赖，必须明确说明范围变化；第二阶段已列目标不能以“暂不实现”静默删除。

实施中记录任务结果、实际命令、失败与未验证范围。完成任务不自动授权 Git 提交、推送、发布或部署。
